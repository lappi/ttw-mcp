# ttw-mcp

MCP-сервер для доступа к рейтингу настольного тенниса
[r.ttw.ru](https://r.ttw.ru): игроки, матчи, очные противостояния, турниры.

Тонкая прослойка получения данных. Сервер не считает аналитику, не хранит
состояние и не кэширует — всю интерпретацию делает модель над JSON.

## Инструменты

| Инструмент | Что возвращает |
| --- | --- |
| `search_players(name, limit=25)` | игроки по фамилии: id, город, `rating_current`, В-П, `hand` |
| `get_player(player_id, include_matches=True, matches_since="")` | профиль: сводка, стартовый рейтинг, периоды, турниры, матчи с рейтингом игрока на момент матча |
| `get_head_to_head(player_id, opponent_id)` | очное противостояние и все встречи |
| `search_tournaments(name="", date="", date_from="", date_to="", enrich=False)` | турниры по названию, дате или диапазону дат |
| `get_tournament(tournament_id, ratings_at_event=False)` | метаданные, итоговая таблица, турниры серии |
| `get_tournament_matches(tournament_id)` | матчи турнира, восстановленные из профилей участников |
| `get_series(tournament_id, limit=10)` | турниры той же серии из двух источников |

`get_tournament_matches`, `get_series` и `get_tournament` с
`ratings_at_event=True` сначала загружают саму страницу турнира, а потом
профиль каждого участника — запросов на один больше, чем участников, и на
крупном турнире это минуты последовательных обращений. `search_tournaments`
с `enrich=True` стоит по запросу на строку, до двадцати: это потолок на
число обогащаемых строк, а не на размер одного ответа, и при диапазоне дат
склейка за несколько дней может дать больше строк, чем потолок позволяет
обогатить, — тогда инструмент отказывается целиком, а не обогащает часть.

Для `search_tournaments` нужен хотя бы один из аргументов `name`, `date`
или диапазон `date_from`/`date_to` (порознь с `date`); для `search_players`
обязателен `name`. Дата — в формате DD.MM.YYYY.

## Установка

```json
{
  "mcpServers": {
    "ttw": {
      "type": "stdio",
      "command": "uv",
      "args": ["--directory", "/Users/lappi/Work/ai/ttw-mcp", "run", "ttw-mcp"]
    }
  }
}
```

Конфигурации и секретов не требуется: источник публичный.

## Ограничения источника

- История не ограничена окном: замерено от 19 до 94 недельных периодов у
  разных игроков, самый ранний — октябрь 2023 года. Глубина зависит от того,
  как давно играет сам игрок.
- `rating_current` в таблице турнира и в поиске игроков — сегодняшнее
  значение, а не рейтинг на день события. Отдельных матчей страница
  турнира не содержит вовсе — их восстанавливает `get_tournament_matches`
  из профилей участников. Восстановленный рейтинг на дату турнира даёт
  `get_tournament(..., ratings_at_event=True)`: добавляет каждой строке
  `rating_at_event`, которое может быть `null`.
- Исход матча (`result`) принимает шесть значений: `win`, `loss`,
  `walkover_win`, `walkover_loss`, `not_played`, `unparsed`.
  `not_played` (счёт 0:0, матч не сыгран) не считается ни победой, ни
  поражением.
- Пометка руки вынесена из имени в поле `hand`. Сайт заводит под
  нерабочую руку отдельный профиль с отдельным идентификатором, поэтому
  один человек может иметь несколько профилей с разными id — сервер их не
  связывает.
- `summary["rating_min"]`, `["rating_max"]` и `["rating_avg"]` в профиле —
  не значения за карьеру, а величины в пределах окна примерно в тридцать
  периодов: у игрока с 87 периодами сводка показывает минимум 150.04 при
  настоящем минимуме 70.31 по `periods`.
- `summary["rated_periods"]` упирается в 30 и у активных игроков занижает
  число периодов. Считать надо по длине `periods`.
- Поиск игроков режется на 500 строках, турниров — на 20 в одном запросе,
  пагинации нет.
- Блок `summary` в профиле отстаёт на один недельный период от списка
  матчей. Для подсчётов используйте `matches`.
- Сайт отвечает за 4–17 секунд. Запросы идут последовательно намеренно.

## Разработка

Тесты парсеров работают на сохранённых страницах сайта. В репозитории их
нет: они содержат ФИО реальных игроков, а r.ttw.ru просит не обходить себя
автоматически. Поэтому перед первым прогоном их надо получить — это
четырнадцать запросов с паузами, около полутора минут:

```bash
uv run python scripts/fetch_fixtures.py   # получить/обновить фикстуры
uv run pytest                             # 219 тестов, без сети
uv run pytest -m smoke                    # 4 теста против живого сайта
```

Без фикстур `pytest` сообщит, каким скриптом их восстановить.

`docs/superpowers/specs/2026-09-22-improvements-design.md`.
